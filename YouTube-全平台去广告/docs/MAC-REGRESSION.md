## 回归工具

播放器广告优先回归是默认范围：

```bash
node tools/mac-chrome-regression.cjs --scope player --rounds 3
```

需要检查首页、搜索、Shorts、频道、播放列表、直播和嵌入页时再运行完整矩阵：

```bash
node tools/mac-chrome-regression.cjs --scope full --rounds 3
```

匿名测试资料持续触发 YouTube 登录或机器人门槛时，使用独立的持久资料目录运行可见 Chrome，首次手工登录后可在后续回归中复用：

```bash
HEADLESS=0 node tools/mac-chrome-regression.cjs \
  --profile-dir "$HOME/Library/Application Support/YouTube-AdBlock-Test-Chrome" \
  --scope full --rounds 3
```

该目录必须是专用测试资料，不能指向正在使用的 Chrome 默认资料目录。工具不会删除持久目录，也不会把其中的 Cookie 或账号数据写入仓库；未指定 `--profile-dir` 时仍使用运行后自动删除的临时资料。

报告会分别输出：

- `preroll=verified`：真实前贴片广告态和正片恢复均被观察到。
- `midroll=verified`：跳转断点后真实中插广告态和恢复均被观察到。
- `adbreak=verified`：真实 `player/ad_break` 响应已读取，响应中没有残留中插广告字段。
- `not-observed`：本轮没有投放对应广告，不得解释为广告处理已经验证。
- `failed`：观察到广告态，但播放器没有正确恢复。

历史回归时 Surge 有效配置为三条脚本各 1 次；从 `1.2.7` 起 Mac 网页安全版移除原生 protobuf 脚本，当前应只检查两条网页脚本各 1 次。旧的 `/tmp/youtube-adblock-local` 模块已停用，当前模块使用项目 `dist` 脚本路径。

## Safari 共享脚本验证

Safari 和 Chrome 使用同一份 `youtube-web-response.js` 与 `youtube-web-page.js`，没有维护浏览器专用副本。本轮 Safari 真页观察到：

- `ZVPm1kqDScU` 先出现约 50 秒前贴片，模块把广告画面隐藏；约 2.5 秒后播放器切换为 1:39:40 正片，声音、进度和正常倍速恢复。
- `RsQ4ZEezufE` 的非 DRM 正片画面可见并持续播放，排除了 Safari 共用脚本导致持续黑屏或播放器停滞。
- Safari 当前未启用“开发 > 允许远程自动化”，因此尚不能读取该浏览器的 DOM 运行时对象和控制台日志。此项保持自动化证据 `unverified`，不能用可见播放结果代替脚本内部诊断。

## 证据边界

- `1.2.4` 当前已验证真实前贴片处理和模块关闭/开启后的 `player/ad_break` 中插调度差异。
- Shorts 当前有真实登录 Chrome 的 3 轮刷新与连续播放证据；匿名无头 Chrome 的不可用提示不作为产品失败证据。
- 真实中插广告画面本身的模块关闭/开启 A/B 尚未在本轮投放出来，状态保持 `unverified`。
- YouTube 会按账号、地区、影片和实验组改变广告结构，单次通过不等于永久或所有账号零广告。
- iPhone/iPad 原生 App、移动网页和 Apple TV 必须各自做真机回归，不能复用本文档作为通过证据。
