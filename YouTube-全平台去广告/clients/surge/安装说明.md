# Surge 一键安装说明

本文对应版本 `1.2.11`。现在分为两个 Surge 模块：Mac 使用不解密 `googlevideo` 的网页安全版，iPhone、iPad 和 Apple TV 使用包含本地 UMP 解密及 tvOS JSON 回退的原生版。两个模块都不会写入、上传或分发你的 Surge 证书、CA 私钥、账号和现有配置。

Surge Mac 6.7.0 实测使用旧式参数占位符语法：模块参数写作 `key:value`，规则中写作 `{{{key}}}`。不要把它改成 `key=value` 或 `%key%`，否则该版本可能提示参数值不存在并拒绝加载模块。

## 一键安装

在安装了 Surge 的设备上，用 Safari 打开与设备对应的 HTTPS 入口：

- [Mac 网页安全版一键安装](https://cndxf.github.io/lab/surge-install.html)
- [iPhone / iPad / Apple TV 原生版一键安装](https://cndxf.github.io/lab/surge-install-native.html)

如果中转页无法唤起 Surge，将对应模块地址填入 Surge 的“从 URL 安装模块”入口：

```text
# Mac
https://raw.githubusercontent.com/cndxf/lab/main/dist/youtube/YouTube-AdBlock.sgmodule

# iPhone / iPad / Apple TV
https://raw.githubusercontent.com/cndxf/lab/main/dist/youtube/YouTube-iOS-tvOS-AdBlock.sgmodule
```

安装预览中，Mac 应显示 `YouTube 全平台去广告 v1.2.11`，iPhone/iPad 应显示 `YouTube iOS/tvOS 去广告 v1.2.11`。模块名称中的 `v1.2.11` 就是当前安装版本，可在 Surge 的模块列表中直接查看。每次更新后应确认名称版本与项目版本一致。同一设备只启用其中一个；也不要同时启用其他会处理 `youtubei.googleapis.com`、`www.youtube.com` 或 `*.googlevideo.com` 的 YouTube 模块，否则重复 MITM 和重复脚本可能造成黑屏、循环加载或无法播放。

### 启用前必须检查全局 MITM

在打开模块开关前，进入 Surge 的 MITM/HTTPS 捕获设置，确认有效配置中没有单独的：

```text
hostname = *
```

也不要开启“捕获全部 HTTPS”。本项目模块使用 `hostname = %APPEND% ...` 只追加 YouTube 所需主机，不能替已有的全局通配符；保留 `*` 会让 Bilibili、银行等证书固定应用在 TLS 握手后主动断开，表现为很多网站都打不开。网页模块只需要 YouTube 三个主机；iOS/tvOS 原生模块再增加 `*.googlevideo.com`。

### 从旧单模块升级

1. Mac 上保留或替换为名称带当前版本号的 `YouTube 全平台去广告 v1.2.11`，不要安装 iOS/tvOS 原生版。
2. iPhone/iPad 上先停用并删除旧的 `YouTube 全平台去广告`，再安装名称带当前版本号的 `YouTube iOS/tvOS 去广告 v1.2.11`。
3. Apple TV 使用 Surge iOS 部署配置时，确认部署后的 tvOS 配置只包含原生版规则，不要同时带入旧单模块。
4. 更新后强制退出 YouTube 并重新启动；若 Surge 的修改后配置中同一 URL 出现两条 YouTube 脚本，先处理重复模块再测试播放。

### 未发布版本的局域网真机测试

新版本尚未推送到 GitHub 时，不要把正式模块中的脚本地址永久改成本机地址。应在项目目录启动一次性测试服务器。Mac 网页候选使用 `--platform web`：

```bash
node tools/serve-local-test.mjs \
  --platform web \
  --allow-lan \
  --host 0.0.0.0 \
  --advertise-host <Mac-LAN-IP> \
  --port 8765
```

iPhone/iPad 或 Apple TV 原生候选使用 `--platform native`；不填写时默认也是原生版：

```bash
node tools/serve-local-test.mjs \
  --platform native \
  --allow-lan \
  --host 0.0.0.0 \
  --advertise-host <Mac-LAN-IP> \
  --port 8765
```

`--allow-lan` 是显式开启局域网监听的安全开关。`<Mac-LAN-IP>` 填 Mac 当前物理局域网地址，例如 Wi-Fi 的 `192.168.31.x`，不要填写 `127.0.0.1`、`0.0.0.0`、Surge TUN 的 `198.18.x.x` 或其他 VPN 地址。

服务器每次启动都会生成新的随机访问 token。iPhone/iPad 与 Mac 连接同一可信局域网后，用 Safari 打开终端输出的 `Local YouTube test server:` 完整地址；地址末尾必须包含 `?token=...`，不要删除、复用或把该地址发给其他人。没有正确 token 的安装页、模块、脚本和健康检查都会返回 `404`。

启动前工具会核对源码与 `dist/youtube` 的版本、模块和五个脚本；任何一项过期都会拒绝启动。安装页只导入临时生成的 iOS/tvOS 原生模块，脚本也只从这台 Mac 的受控目录读取。它不会修改正式模块、主配置或 GitHub 分发文件。若 macOS 防火墙询问是否允许 Node 接收入站连接，只在当前可信局域网测试时允许。

测试结束后按 `Control-C` 停止本地服务器，再删除或停用设备上的本地测试模块，避免手机离开当前局域网后继续引用不可达的脚本地址。正式发布后重新从 HTTPS 一键安装入口覆盖安装。

### 安装与启用

安装完成不等于启用。Surge 只把模块保存到设备，仍需进入模块列表打开启用开关；Mac、iPhone、iPad 等每台设备单独启用，不能依靠另一台设备的开关状态。

Mac 网页安全版会注入 2 条网页脚本规则；iOS/tvOS 原生版会注入 7 条脚本规则，其中 1 条是 tvOS JSON `player` 回退规则。它们会合并到 Surge 的“修改后的有效配置”中，不会复制到主配置。Mac 可在项目目录运行：

```bash
./tools/check-surge-effective.sh
```

该脚本检查 Mac 当前有效配置中的 2 条网页规则，并确认网页响应规则包含 `player/ad_break`。若显示 `DUPLICATE`，说明新旧模块同时启用；若显示 `STALE`，说明当前仍在使用旧模块。

### 为什么分为两个模块

网页规则和原生 App 规则仍会按 URL 自动分流，但 `*.googlevideo.com/initplayback` MITM 对 Mac 浏览器有过播放安全风险，因此不再强制所有平台共用一个模块：

- Mac 网页安全版：只处理 `www.youtube.com`、`m.youtube.com` 和 `youtubei.googleapis.com`，不 MITM `googlevideo`。
- iOS/tvOS 原生版：包含上述网页规则，另外处理 `youtubei` protobuf 和 `googlevideo/initplayback` UMP 加密播放流。
- Surge 的 MITM hostname 只能按主机名配置，因此原生版会对 `*.googlevideo.com` 建立 MITM；真正执行脚本的规则仍只匹配 `initplayback`。其他 `googlevideo` 路径不会执行本模块脚本，但仍处于该 CA 的 TLS 解密范围内。
- UMP 解密、广告字段清理、gzip、AES-CTR 重新加密和 HMAC 均在设备本地执行，不使用第三方 Worker。
- Apple TV 目前复用原生候选路径，完成 tvOS 真机验证前仍标记为实验性。

每台设备仍需要单独启用模块、安装并信任 CA。

## 模块参数设置

Surge 当前把模块参数显示为输入项，不提供模块作者可声明的原生开关或下拉框。布尔参数请输入小写 `true` 或 `false`；默认值已经按副作用最小的方式设置。

| 参数 | 默认值 | 作用范围 | 说明 |
| --- | --- | --- | --- |
| `caption_lang` | `off` | iPhone/iPad 原生 App | 字幕翻译语言；可填 `zh-Hans`、`zh-Hant`、`en` 等语言代码 |
| `block_upload` | `false` | iPhone/iPad 原生 App | `true` 时隐藏上传按钮 |
| `block_immersive` | `false` | iPhone/iPad 原生 App | `true` 时隐藏选段/沉浸式入口 |
| `block_shorts` | `false` | iPhone/iPad 原生 App | `true` 时隐藏 Shorts 入口 |
| `debug` | `false` | 当前模块内的所有脚本 | `true` 时开启脚本调试日志，仅排障时使用 |
| `update_interval` | `21600` | 当前模块内的所有脚本 | 远程脚本更新检查间隔，单位秒；默认每 6 小时 |

网页播放速度属于网页播放器功能，会在播放器里直接选择并自动保存，不使用模块参数输入框。

## iPhone / iPad 证书安装

1. 在 Surge 中进入 MITM 设置，生成并安装 Surge CA 证书。不同版本的菜单名称可能显示为“MITM”“证书”或“配置根证书”。
2. 系统下载描述文件后，打开“设置 > 通用 > VPN 与设备管理”，选择刚下载的 Surge 证书描述文件并完成安装。
3. 再打开“设置 > 通用 > 关于本机 > 证书信任设置”，为该 Surge 根证书开启完全信任。
4. 返回 Surge，确认 MITM 和脚本功能均已启用，再启用本模块。
5. 强制退出 YouTube App 和浏览器后重新打开，避免旧 TLS 连接继续绕过 MITM。

证书只需首次安装和信任。更新模块或脚本时不需要重复安装证书；只有证书被删除、过期或重新生成后才需要重新信任。

## macOS 证书安装

1. 在 Surge Mac 的 MITM 设置中生成证书，并执行安装到系统钥匙串。
2. 如果 Surge 仍提示证书不受信任，打开“钥匙串访问”，找到对应的 Surge 根证书，打开“显示简介 > 信任”，将 SSL 信任设为“始终信任”。
3. 退出并重新打开 Safari、Chrome 和 YouTube 页面，让浏览器建立新的 TLS 连接。
4. 在 Surge 中确认 MITM、脚本和本模块均处于启用状态。

## Apple TV

Apple TV 当前属于实验支持。在 Surge iOS 中安装并启用 `YouTube iOS/tvOS 去广告`，再把配置和证书重新部署到 Apple TV。tvOS 必须安装并信任对应 CA；完成前贴片、中插、长视频和播放恢复验证前，不得把 Apple TV 标记为已验证支持。

部署后可从 Mac 远程检查 Apple TV 的有效配置。将远程控制器密码和地址替换为当前设备值，不要把命令或输出提交到仓库：

```bash
SURGE_REMOTE='[REDACTED]@APPLE_TV_IP:6170' \
  ./tools/check-surge-native-effective.sh
```

检查必须同时通过 `youtube.native.response`、`youtube.native.request.init`、`youtube.native.response.init`、`youtube.tvos.json`，并确认有效配置的 MITM 包含 `*.googlevideo.com`。只有配置检查通过后，才进入 YouTube 前贴片、中插和长视频恢复测试；仅能 ping 通或看到 Surge 在线不能算部署完成。

## 更新模块与脚本

两个模块都安装自固定 URL，后续版本继续使用各自的一键安装链接：

1. 在 Surge 的已安装模块列表中点击刷新或更新按钮，可立即拉取最新模块。
2. 再次点击与设备对应的一键安装链接，可以覆盖安装最新版；如果 Surge 提示名称重复，选择替换。
3. 远程脚本规则默认设置 `update_interval=21600`，Surge 每 6 小时检查脚本更新；可在模块参数中调整。
4. 每次发布都会使用新的 `releases/<版本>/scripts/` 目录，并同步 `?v=` 参数；旧模块继续引用旧版本脚本，不会被 `main` 分支的新脚本静默覆盖。
5. 更新后强制退出 YouTube App 或关闭所有 YouTube 标签页，再重新打开进行验证。

发布到 GitHub 前，在仓库目录运行：

```bash
./tools/check-published.sh
```

也可以把公开分发检查并入完整验证：

```bash
CHECK_PUBLISHED=1 ./tools/verify.sh
```

这个检查会逐个下载两个公开模块、五个脚本、`VERSION` 和哈希文件，确认 GitHub 与本地分发目录完全一致。开发本地 HTTP 分发时可显式设置 `YOUTUBE_DIST_BASE_URL`，并同时设置 `ALLOW_LOCAL=1`；正式发布检查不要使用本地地址。

发布或开始新一轮真机回归前，运行实时上游审计：

```bash
AUDIT_UPSTREAM=1 ./tools/verify.sh
```

该检查会核对 Maasea 原生 protobuf 脚本提交，以及 uBlock Origin 和 AdGuard 当前的 YouTube 广告字段块。任意一项与已审核基线不同都会中止严格验证，需要先比对上游差异再更新基线。

如果网络较慢，可临时设置 `YOUTUBE_AUDIT_MAX_TIME=180` 延长上游文件下载超时；默认值为 120 秒。该参数只影响发布前审计，不会改变设备上的拦截逻辑。

## 验证

1. 打开 Surge 最近请求，确认 `www.youtube.com`、`m.youtube.com` 或 `youtubei.googleapis.com` 的请求已进入 MITM 和对应脚本。原生版还要确认 `*.googlevideo.com/initplayback` 命中 request/response 脚本。
2. 网页端依次检查首页、搜索、普通视频、Shorts 和长视频；广告结束后必须恢复原静音状态、播放速度和画面。
3. iPhone / iPad 原生 App 依次检查首页信息流、前贴片、中插、Shorts 和长视频。
4. Apple TV 的验证结果单独记录，不使用网页或手机结果代替 tvOS 真机结果。

## 常见问题

### 显示证书错误或连接不安全

- 重新检查系统的证书信任设置，而不只是“已安装描述文件”。
- 打开当前配置的 `[MITM]`，确认 `hostname` 中没有单独的 `*` 全局通配符。模块使用 `%APPEND%` 只追加 YouTube 所需主机，不能替已有的全局 `*`；全局解密会让 Bilibili、银行等证书固定应用主动断开 TLS 握手，也可能在 CA 未完全信任时造成大量网站不可用。
- 原生模块建议只保留 `www.youtube.com`、`m.youtube.com`、`youtubei.googleapis.com` 和 `*.googlevideo.com`；网页模块不需要 `*.googlevideo.com`。修改后点击应用并重启 Surge，再重新建立连接。
- 检查 Mac、iPhone/iPad 和 Apple TV 的“日期与时间”均已开启自动设置，并且日期、时区一致；即使只相差一天也可能导致 TLS 证书、Surge MITM 或 Xcode 配对失败。
- 关闭其他 HTTPS 解密工具，避免多个 CA 同时接管同一连接。
- 退出浏览器或 App 后重新建立连接。

### 视频无法播放、一直转圈或黑屏

- 暂时关闭本模块确认问题是否消失。
- 检查并停用旧 YouTube 模块中的 `*.googlevideo.com` MITM、`initplayback` 请求改写和重复的 `youtubei` 响应脚本。
- Mac 网页安全版故意不 MITM `*.googlevideo.com`，因为该路径曾造成网页播放异常。
- iOS/tvOS 原生版会 MITM `*.googlevideo.com`；若关闭原生版后立即恢复播放，记录 YouTube 版本、设备系统、视频位置和 Surge 脚本错误，不要同时打开基础模块绕过问题。
- 更新模块后重启 Surge 和 YouTube，再测试同一个视频。

### 广告仍然出现

- 在模块列表执行“更新模块”，确认脚本 URL 中的版本与项目 `VERSION` 一致。
- 检查请求是否绕过 Surge、MITM 或脚本处理。
- YouTube 会持续改变广告结构；请记录平台、客户端版本、视频链接、广告出现位置和 Surge 脚本日志，避免只报告“还有广告”而无法定位。

## 回滚

1. 在 Surge 的模块列表中停用当前设备使用的 `YouTube 全平台去广告 v1.2.11` 或 `YouTube iOS/tvOS 去广告 v1.2.11`。
2. 重新加载当前配置并重启 YouTube，确认播放恢复。
3. 需要彻底移除时删除该模块。因为它没有直接改写主配置文件，所以不需要手工删除 `[MITM]` 或 `[Script]` 行。
4. 如果仍有相同规则，说明旧配置或其他模块还保留了 YouTube 相关脚本，需要单独检查。
